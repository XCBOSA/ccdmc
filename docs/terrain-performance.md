# 地形流送与网格性能验收

用同一份存档、游戏设置和宿主版本做对照。基准路线从自然世界种子 `992382978` 的
`(32.50, 122.01, 8.50)` 起飞，面向负 Z，持续按屏幕摇杆 16 秒，跨 9 个区块，
松开后右转视角，再保存并读回坐标。保留停下、刚转向和等待补齐三张原图。自然地形之外，
用一条人工栈道检查大量编辑和超平坦加载。不要用测试通过替代截图检查。

把三种结果分开报告：

- 基本正确性：对应快照的普通顶点和水面顶点逐字节对照，覆盖跨区块接缝、高 ID 方块和不同光照。
- 算法成本：在同一个 CCD 进程内，对同一个快照交替执行旧路径和候选。轮换先后顺序，不把热缓存、
  原生执行耗时或输出几何减少造成的差异算成候选提速。
- 游戏表现：同路线操作两个版本，记录区块就绪、网格发布、回调执行和两次回调间的等待。网格作业以
  区块坐标、几何版本、普通与水面顶点数、是否携带过渡或精确光照配对。整段均值包含不同的工单时，
  不能拿它替代配对结果。记录尺度是游戏回调，不是屏幕扫描帧。

## 一次未通过的优化

天光近邻短路与普通面的贴图查表在同进程配对探针中，把 24 组网格的平均烘焙从约 330 ms 降到
247 ms，普通和水面顶点完全一致。但正常飞行的反序对照里，7 个可配对任务的均值从约 388 ms
升到 453 ms，转向后 13 个任务才从约 270 ms 降到 254 ms。持续飞行没有稳定受益，未上线。

同一基线飞行样本的 15 次完成烘焙中，4 次是已显示的同坐标、同几何版本和同顶点量的区块从
临时光照升级到精确光照，合计约 1.66 秒 worker 耗时。这些不是错误的光照工作；仍要验证的是，
何时该先补没显示的远坡、何时该完成光照更新。调度方案不能推迟用户刚编辑的近处方块，
也不能永久饿死精确光照或靠缩短视距隐藏缺块。复验同时检查移动、停下、转向以及近处编辑。
